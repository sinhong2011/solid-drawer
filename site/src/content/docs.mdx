## About

`@sinhong2011/solid-drawer` is the primitive: unstyled parts that move themselves with inline `transform` and `transition`, and a `useDrawer()` that reads back where the drawer is. Where it sits, and what it looks like, is yours.

This page documents the styled component, `components/ui/drawer.tsx`, which you copy in the installation step. The demos on the front page use the same file.

## Examples

### Snap points

A number is a fraction of the **container** - the `container` element if you gave one, else the content's positioned ancestor, else the window. A string is pixels. Both mean _how much of the drawer shows_: the content keeps its own height and is translated so that much of it is on screen.

<Callout type="warn" title="Give it a height">
  The component's `max-h-[80vh]` and auto height are for a plain sheet. A drawer with snap points
  needs a height of its own, at least as tall as the largest snap point - `h-[92dvh] max-h-none!` in
  the example.
</Callout>

## API reference

### Root

Everything is optional. `SnapPoint` is `number | string`: a fraction of the container, or a pixel length like `"320px"`.

<PropsTable rows={rootProps} />

### Parts

The primitives, as `Drawer.*` from the package. The component above wraps them.

- **`Root`** / **`NestedRoot`** - state. A `NestedRoot` inside another drawer's tree scales that drawer back as it opens and follows its drag.
- **`Portal`** - into `container` or the body. Skip it for a drawer that stays inside its panel.
- **`Overlay`** - opacity follows the drawer (solid from `fadeFromIndex`, fading below it). Position it yourself.
- **`Content`** - `role="dialog"`, labelled by `Title`/`Description`, `touch-action: none`. Position it yourself.
- **`Handle`** - a 44px tap target; a tap goes to the next snap point (or closes from the last), `preventCycle` turns that off.
- **`Trigger`**, **`Close`**, **`Title`**, **`Description`** - take `as` to render as something else.

Anything inside the content that scrolls should carry `touch-action: pan-y` (`pan-x` for a side drawer); mark things that must never start a drag with `data-drawer-no-drag`.

### Data attributes

To style against. The content carries all of these; the overlay and the handle carry `data-drawer-direction`.

## Coming from Vaul

The props and parts have Vaul's names, so a Vaul drawer moves over as it is. What is different:

- Snap point fractions are of the container (as Vaul) but the offset is computed from the drawer's own height, so `"320px"` shows exactly 320px whatever height the content has.
- The gesture is heard on `window` from `pointerdown`, so a quick flick from the handle cannot escape the drawer before it counts.
- `breakPoints`, `transitionResize`, `transitionState`, `openPercentage`, `translate`, `velocityThreshold`, `dampFunction`, `transitionDuration`/`transitionEasing` are additions.
- Not ported: the 500ms "just opened" drag lock, `repositionInputs`' Firefox-on-Android special case, `noBodyStyles` splitting from `setBackgroundColorOnScale`.
